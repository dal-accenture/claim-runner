## Summary

Implement the Benefits Determiner as a FastAPI service (`benefits_determiner/`) on port 8081. Given a member ID, provider ID, list of procedure codes, and date of service, the service calls the Data Service via HTTP to retrieve member and plan records, then applies eligibility, network status, coverage, and authorization rules to produce a structured per-line determination. Returns `503` if the Data Service is unreachable, `422` for malformed requests, and `200` with a determination payload on success.

---

## Technical Context

**Language/Version**: Python 3.11+

**Primary Dependencies**:
- `fastapi` — web framework (constitution requirement)
- `uvicorn` — ASGI server
- `httpx` — HTTP client for Data Service calls (sync client; no async needed at practicum scale)
- `pydantic` — request/response validation (pulled in by FastAPI)
- `pytest` + `respx` — test runner + httpx mock library for unit and integration tests

**Storage**: N/A — no direct file access; all data via HTTP to Data Service

**Testing**: pytest with FastAPI `TestClient` for API tests; `respx` to mock `httpx` calls to Data Service without needing a live Data Service running

**Target Platform**: Single-machine (practicum); Linux/Windows compatible

**Project Type**: web-service

**Performance Goals**: Practicum-scale (200 members, 150 claims); no throughput or latency targets

**Constraints**:
- Independently startable without Claims Manager or Pricer
- `DATA_SERVICE_URL` env var sets Data Service base URL; default `http://localhost:8083`
- No direct file access to `data/`
- Returns `503` (not `500`) when Data Service is unreachable during a request
- Startup must log port and `DATA_SERVICE_URL` to stdout

### Source Code (repository root)

```text
benefits_determiner/
├── main.py              # FastAPI app, /health, /benefits/determine endpoint, startup log
├── models.py            # Pydantic request and response models
├── determination.py     # Pure determination logic (no HTTP); takes member dict + plan dict
├── data_client.py       # httpx wrapper — GET /members/{id}, GET /plans/{id}; raises DataServiceError
├── requirements.txt     # fastapi, uvicorn, httpx, pydantic
└── tests/
    ├── __init__.py
    ├── test_determination.py   # Unit tests for determination logic (no HTTP)
    └── test_api.py             # Integration tests for POST /benefits/determine (respx mocks Data Service)
```

**Structure Decision**: Single-service layout with one layer of indirection (`data_client.py`) between HTTP concerns and business logic (`determination.py`). The separation makes `determination.py` unit-testable without any HTTP mocking — tests pass raw dicts. `data_client.py` is tested via `respx` in `test_api.py`.
