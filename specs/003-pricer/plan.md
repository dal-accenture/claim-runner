## Summary

Implement the Pricer as a FastAPI service (`pricer/`) on port 8082. Given a claim ID, member ID, plan ID, network status, and a list of covered claim lines, it calls the Data Service for member accumulators and fee schedule rates, then applies cost-sharing logic (deductible → copay → coinsurance → OOP cap) per line with two running counters (`deductible_used_this_claim`, `oop_used_this_claim`) to handle multi-line claims correctly. Returns per-line financial detail plus claim-level totals and an accumulator snapshot. Does not write back to any data file.

## Technical Context

**Language/Version**: Python 3.11+

**Primary Dependencies**:
- `fastapi` — web framework (constitution requirement)
- `uvicorn` — ASGI server
- `httpx` — HTTP client for Data Service calls (synchronous, consistent with Benefits Determiner)
- `pydantic` — request/response validation
- `pytest` + `respx` — test runner + httpx mock library

**Storage**: N/A — all data via HTTP to Data Service; no direct file access

**Testing**: pytest with FastAPI `TestClient`; `respx` to mock Data Service calls without needing a live service

**Target Platform**: Single-machine (practicum); Linux/Windows compatible

**Project Type**: web-service

**Performance Goals**: Practicum-scale; no throughput or latency targets

**Constraints**:
- Independently startable without Claims Manager or Benefits Determiner
- `DATA_SERVICE_URL` env var (default `http://localhost:8083`)
- `PORT` env var (default `8082`)
- Returns `503` when Data Service is unreachable; `404` when member or plan not found; `422` when procedure code not in fee schedules
- Startup must log port and `DATA_SERVICE_URL` to stdout
- No file writes; accumulator snapshot is informational only

├── pricing.py           # Pure pricing logic — price_claim(member, fee_schedules, request) -> PriceResponse
├── data_client.py       # httpx wrapper — get_member, get_plan, get_fee_schedule; raises DataServiceError
├── requirements.txt     # fastapi, uvicorn, httpx, pydantic
└── tests/

**Structure Decision**: Same layered pattern as Benefits Determiner — `data_client.py` for HTTP concerns, `pricing.py` for pure business logic, `main.py` for routing and error mapping. `pricing.py` takes plain dicts and returns Pydantic models, so it is fully unit-testable without any HTTP mocking.
